# QA Testing Course

This repository documents my progress through a Quality Assurance (QA) testing course. It is a lightweight study space for theory, practical exercises, reusable testing artifacts, evidence, and course projects.

## Learning Goals

- Build a solid foundation in software quality assurance.
- Practice manual, web, API, and automated testing.
- Learn how to design, execute, and document tests clearly.
- Create reusable test plans, test cases, checklists, and bug reports.
- Keep a visible record of my learning progress and practical work.
- Become progressively more comfortable reading technical documentation in English.

## Language Approach

English is introduced progressively without making the Spanish-language course harder to follow:

- Every `README.md` is written entirely in English.
- Titles and section headings in all documentation are written in English.
- The body of study notes and other non-README documents is written in Spanish.
- Common QA and software terms may remain in English when that is standard industry usage.

## Course Structure

The virtual course is organized around introductory sections, 16 numbered classes, a project pre-delivery, and a final project. This repository follows the class sequence without copying unnecessary platform complexity.

## Repository Structure

```text
QA-testing-course/
├── notes/            # Class notes, summaries, and glossary
├── exercises/        # Hands-on practice grouped by testing area
├── test-artifacts/   # Test plans, test cases, checklists, and bug reports
├── projects/         # Course assignments and portfolio projects
├── progress/         # Course progress and evidence references
├── resources/        # References, useful links, books, and tools
├── assets/           # Screenshots, diagrams, and supporting files
└── templates/        # Reusable Markdown templates
```

Each main directory contains a short guide explaining what belongs there.

## Naming Conventions

- Use English `kebab-case` names without spaces, accents, or special characters.
- Name class folders `class-NN-short-topic`, for example `class-02-software-development-and-qa`.
- Name screenshots `class-NN-activity-descriptor.ext`, for example `class-02-quiz-result.png`.
- Add an ISO date (`YYYY-MM-DD`) only when chronology is useful.
- Keep the conventional uppercase filename `README.md` for repository and directory guides.

## Suggested Study Workflow

1. Create a class folder under [`notes/classes/`](notes/classes/) when the first note for that class is added.
2. Record the main ideas using the note template.
3. Complete practical work under [`exercises/`](exercises/).
4. Save formal QA documentation under [`test-artifacts/`](test-artifacts/).
5. Store supporting screenshots or diagrams under [`assets/`](assets/).
6. Update [`progress/course-progress.md`](progress/course-progress.md).

## Repository Status

This is an evolving learning repository. New folders and documents should be added only when they serve real course material, keeping the study workflow simple and low-friction.
